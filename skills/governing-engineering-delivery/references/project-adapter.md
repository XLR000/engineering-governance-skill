# Project Adapter

Read this when applying the workflow to a repository for the first time.

1. Inspect the repository's instruction files, product documents, commands, Git state, runtime, data boundaries, and existing failures before changing anything.
2. Treat existing project rules as the local source of truth. Reuse equivalent documents and conventions; do not create a generic document set just to satisfy this skill.
3. If a project needs stronger controls for its own risk, keep them in project-local instructions or documentation. Record live targets, credentials, provider rules, product facts, and evidence only in that project.
4. Use the optional task card only when it will make a handoff or a multi-step change clearer.

Do not copy secrets, production exports, live identifiers, or unrelated conversation history into the reusable skill.
